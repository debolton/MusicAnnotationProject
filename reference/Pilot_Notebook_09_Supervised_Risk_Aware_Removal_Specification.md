**Supervised Pilot Notebook 09**

_Risk-aware annotation removal reviewer: product specification and implementation work plan_

Music Annotation Project | 13 October 2026

**Core decision: build a supervised review-by-exception product now. No component is silently auto-accepted. The pilot reuses the equivalent V7.8 structural implementation and the frozen V7.7F policy bundle; it does not create another structural algorithm.**

# 1. Product goal

Take an annotated-only music page, reuse the existing detector confidence products, construct the frozen geometry_t80 proposal, score each component with V7.7F, and present the result in the existing single-canvas reviewer style. The operator approves, rejects or edits every final page. The product milestone is a useful cleaned score plus an intelligible audit trail, not unattended automation.

# 2. Non-negotiable safety boundaries

- No clean target is required or read.
- No model training, recalibration or threshold tuning occurs.
- No pixel outside the authorised removal mask may change.
- YOLO confidence and structural safety remain separate values.
- A reviewed corrected mask overrides a draft mask.
- Green means recommended for batch human confirmation, not auto-accepted.
- The frozen V7.7F artefact hashes and policy ID must pass before the application opens.

# 4. Pilot workflow

| **Stage**      | **Behaviour**                                                                                                                                                                                                                       |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Detect         | Read an existing confidence map and draft mask generated by the established HITL GPU generator. Pilot 09 does not train YOLO.                                                                                                       |
| Authorise mask | Prefer a reviewed corrected mask. Otherwise use the draft mask and mark the page as requiring mask confirmation.                                                                                                                    |
| Reconstruct    | Build dilation-2 removal mask, Telea preview, geometry_t80 proposal and routing maps.                                                                                                                                               |
| Score          | Build component predictors and apply the frozen V7.7F model, calibrator and threshold.                                                                                                                                              |
| Route          | Green: passes structural threshold; amber: does not pass; red: conservative leave-unchanged recommendation for high reconstruction dependency or protected-geometry overlap. These are pilot routing labels, not new model classes. |
| Review         | Use the canvas to view original/proposal/routing, edit the annotation mask, accept a component, leave unchanged, or accept all green recommendations.                                                                               |
| Approve        | Require final human page approval and an outside-mask immutability check.                                                                                                                                                           |
| Audit          | Save source/model/policy hashes, raw confidence, authoritative mask, routing maps, component evidence, proposed page and human decisions separately.                                                                                |

# 5. User interface specification

- Full-page single canvas with bounded wheel scrolling, pointer-centred Ctrl+wheel zoom and pan.
- Overlay toggles for annotation evidence, structural category, preserve/remove/ambiguous routing and final mask.
- Component queue sorted red, amber, then green; navigation by component and page.
- Component evidence card showing annotation evidence, structural probability, frozen threshold and routing fractions.
- Buttons: Accept component, Leave unchanged, Edit mask, Accept all green, Reset page, Approve final page.
- Final approval summary showing accepted, unchanged, edited and unresolved counts.

# 7. Product success criteria

- A real annotated-only page can be processed without clean truth.
- The operator can review primarily exceptions, while confirming green items in a batch.
- A corrected final page is produced with zero outside-mask drift.
- Every component decision can be traced to annotation evidence, routing evidence, policy identity and human action.
- The operator would choose the workflow for the next batch rather than manually cleaning the complete page.

# 8. Implementation status and limitation

The accompanying notebook implements the read-only policy integrity gate, the canonical structural pipeline, component scoring, proposal generation, pilot routing, output/audit preparation and a Gradio review interface. The UI is a first pilot implementation rather than a pixel-perfect merger of every JavaScript line in the existing reviewer. The structural pipeline is the controlled part: it is copied from the V7.8 implementation and explicitly fingerprinted.
